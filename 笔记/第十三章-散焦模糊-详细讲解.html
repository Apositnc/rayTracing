先看故事：为什么小熊清楚，后面的花却糊了？

先用生活里的话说：给小熊拍照，你想让小熊的眼睛清清楚楚，让后面的花变成软软的一团。你可以把相机想成一群站在不同位置的小朋友：他们都盯住小熊眼睛，但从各自位置看过去，后面的花会错开。把他们的画面叠在一起，小熊对齐了，花却散开了。

这群“小朋友”对应的是镜头圆盘上的不同射线起点。这个比喻帮助理解几何，但代码并不是建立很多完整相机：我们仍用一个相机，每次采样在圆盘里挑一个起点。

共同约定

属于同一个图像采样位置的射线，瞄准对焦平面上的同一点。

本章最关键的变化只有一句：终点先选好，起点可以换；起点换了，方向必须重算。后面的每条公式都在实现这件事。

本章按教材 13.1“薄透镜近似”、13.2“生成采样光线”展开。我们先把清楚与模糊的原因讲通，再写随机采样，最后把它接进你的相机。

13.1① 三种“糊”，先别混成一件事

现象像生活里的什么由什么控制
散焦模糊对准小熊，背景花变成一团focus_dist、defocus_angle
抗锯齿楼梯状的斜边变得平顺像素内部采样与平均
随机噪点图上有一粒粒杂色小沙子样本数不足，增加 samples_per_pixel 可以减少
运动模糊（后续内容）跑动的人拖出一道影子对不同时间采样，本章没实现
金属粗糙反射磨砂金属中的倒影很散材质 fuzz，本章的镜头参数不是它

把采样数增大，可以让“应该模糊的背景”变得更平滑，但不会自动把它对焦。因为噪点是采样不够稳定，散焦是相机模型本来就要平均不同方向的信息。

景深指“看起来足够清晰的深度范围”；散焦模糊指偏离对焦位置时出现的模糊现象。二者有关，但不是完全相同的定义。严格几何上，本模型只有一个平面完全对焦；其他深度是否看起来仍清楚，还取决于模糊斑多大、像素大小和观看要求。

13.1② 针孔、圆孔、透镜，分别做了什么？

先用生活里的话说：针孔像一道只让一个方向通过的小门：从一个世界点到门的位置几乎只有一条路。把门开大以后，同一个世界点可以从门的好多地方穿过。透镜则负责把某个距离来的光重新整理，让它们在感光板上会合。

现实中的光从场景走到相机、最后落在传感器上；我们的渲染器为了计算方便，从相机朝场景追踪。在这类普通几何光学模型里，可以利用光路可逆来理解这种“倒着找路”。

为什么不真的在电脑里造一套相机？

我们可以模拟多片玻璃、透镜曲面、传感器，再处理倒像。但本章的目标只是产生合理的对焦和散焦效果。教材使用薄透镜近似：把镜头抽象为没有厚度的圆盘，用“圆盘起点 → 对焦平面采样点”的直线表示镜头外侧的射线。

它没有模拟色差、镜头畸变、镜片厚度、光圈叶片形状或衍射。理解这些省略很有用：模型简化了光路，但不是随便给图片加一层高斯模糊。

真实摄影里，焦距通常指透镜主平面到焦点的距离（以平行入射光定义）；对焦距离是镜头到对焦物体/平面的距离；像距是到传感器成像面的距离。它们不是一回事。本教程前方的 viewport 是辅助对焦平面，并不是现实相机后方的传感器。不要把旧变量 focal_length 的名字直接套到所有真实光学概念上。

在近轴薄透镜模型中，物距 s、像距 s′ 与焦距 f 满足 1/f = 1/s + 1/s′。本章代码不需要解它，因为已经用“前方的对焦平面 + 镜头圆盘”把主要几何效果直接表达出来了。

13.1③ 对焦平面：先约定在哪里集合

先用生活里的话说：给大家在操场前面放一块透明玻璃板，板上画一个红点。每个小朋友站在后方圆圈里的不同地方，都用手指指向红点。所有指示线在红点会合；在玻璃板前面或后面的另一块板上，它们就会散开。

相机中心是 C，朝后单位方向是 w，对焦距离是 d。对焦平面中心 F 就是：

F = C − focus_dist * w 对焦平面内的点 P 满足：dot(P − C, −w) = focus_dist

“平面与视线垂直”意味着它像正对着你的玻璃板。它不是以相机为球心的一个球壳。两个点到相机的直线距离不同，仍然可以在同一个对焦平面上。

为什么把视口也放在这里？

因为视口本来就存放每个像素的三维采样位置。把它直接放到对焦平面，我们只要计算一次 pixel_sample，就同时知道“这是哪个像素”与“不同镜头起点应该瞄准哪里”。

viewport_h = 2 * focus_dist * tan(vfov/2) viewport_w = viewport_h * 实际图像宽高比 视口中心 = C − focus_dist*w

第 12 章用 length(lookfrom-lookat) 作为辅助视口距离；第 13 章改用独立参数 focus_dist。相关两处要一起改：视口高度和视口摆放位置。只改其中一处会改变视场角，导致本来只想对焦却意外改变取景。

13.1④ 一束线怎样从清楚变成模糊？

为了单独看清几何，先固定对焦平面上的一个采样点 P，暂时不随机移动像素终点。让圆盘中的起点 A 不断变化，射线就是 A + t(P-A)。

在对焦平面处，t=1，所以无论 A 是谁，都到达 P。这是清楚的几何原因。在别的深度，同一像素收到的方向不再对应一个相同的场景点，而覆盖了一个区域。区域中颜色被平均，就呈现模糊。

光线集合实验：看看哪里会合

侧视图展示一个固定像素采样点对应的射线束。橙色是镜头圆盘的截线，绿色是对焦平面，紫色是观察截面。此实验直接调半径以便看清；后面的实际相机使用 defocus_angle。

慢慢算出“散开了多少”

选取相机为原点、前方为深度 z 的局部坐标。镜头起点的横向坐标为 A，固定采样点 P 的横向坐标为 0，对焦平面深度为 d。射线在任意深度 z 的横向位置是：

x(z) = A + (z/d)*(0 − A) = A*(1 − z/d) 当镜头圆盘半径为 R： 同一像素射线束在深度 z 的截面半径 = R*|1 − z/d| 截面直径 = 2R*|1 − z/d|

比如 R=0.6，d=6：在 z=3，半径 0.3；在 z=6，半径 0；在 z=9，半径又是 0.3。请把滑块放到这三个位置看看。

上式是“同一个像素的射线束在世界截面上覆盖多宽”，不是直接以像素为单位的照片模糊斑。若固定一个深度 z 的物点，反过来算它投到本教程虚拟对焦平面的弥散半径，则是 R*|1−d/z|；再除以每个像素的世界长度才能换成像素大小。不要把这两个公式混用。

真实球体有前后厚度，所以把焦平面放在球心附近，也不意味着整颗球每一处都数学上完全对焦；只是许多区域可能已经足够清楚。

13.2① 圆盘多大？用 defocus_angle 控制

先用生活里的话说：刚才让大家站在一个圆圈里。圆圈很小，大家位置差不多，看过去的差异也小；圆圈很大，大家分得更开，焦平面以外的错位就更明显。
C++ · 对照你的项目变量名
double defocus_angle = 0; // 散焦圆锥的完整夹角，单位：度
double focus_dist = 10;  // 到对焦平面的垂直距离，世界单位

defocus_angle 与 vfov 都是角度，但描述不同的圆锥：vfov 的顶点在相机，朝向视口上下沿；defocus_angle 的顶点在对焦平面中心，朝向镜头圆盘的两端。

α = defocus_angle R = focus_dist * tan(α/2) 教材示例：d=3.4，α=10° R = 3.4*tan5° ≈ 0.297461 最终场景：d=10，α=0.6° R = 10*tan0.3° ≈ 0.052360

角度越大，圆盘越大，通常散焦越明显。角度等于 0 时，R=0，圆盘缩成相机中心，回到针孔模型。代码也明确在角度 ≤0 时直接选中心。

为什么不直接暴露半径？

直接用半径当然也能实现。教材选择角度，是希望当投影/对焦距离改变时，镜头圆盘能随几何比例一起缩放，参数更方便。它不保证任意物体在你改变对焦距离以后模糊程度都相同，因为焦平面本身移动了。

本渲染器对像素样本取平均，并没有乘上真实相机的光圈通光面积或曝光时间。因此增大 defocus_angle 不会按照真实曝光规律自动把照片整体变亮。它主要改变采样光路与散焦效果。

参数比喻控制结果
vfov你看世界时张开的视野取景范围
focus_dist集合板放多远哪里对焦
defocus_angle大家分开站得多宽镜头圆盘尺寸及散焦强弱
samples_per_pixel每个像素问多少次估计结果的稳定程度

13.2② 在单位圆盘里随机选一个点

先用生活里的话说：在桌上画一个边长为 2 的正方形，再在里面画一个半径为 1 的圆。闭眼往正方形里扔豆子：落在圆里的留下，落在四个角里的重新扔。留下来的豆子就均匀铺在圆盘里。
C++ · 加在 vec3.h 的工具函数区
inline vec3 random_in_unit_disk() {
    while (true) {
        vec3 p(random_double(-1, 1), random_double(-1, 1), 0);
        if (p.length_squared() < 1) return p;
    }
}

逐行看

  1. while(true)：不断尝试，直到找到合格点就 return。不是故意永远不结束。
  2. random_double(-1,1)：x、y 各选一个随机数，覆盖 [−1,1) 的正方形。
  3. z=0：这是二维圆盘，不是在三维球里撒点。
  4. length_squared() < 1：x²+y²<1，点在圆内部。无需开平方，更直接。
  5. return p：保留原始坐标，不要把它归一化。

圆面积是 π，正方形面积是 4，所以理想均匀采样下接受率为 π/4≈78.54%。平均约 4/π≈1.273 次尝试就得到一个点。这是统计平均，不是每次最多尝试两次。

撒豆子：保留圆内的，拒绝圆外的

绿色是留下的点，灰色是被拒绝的点。每一批都重新生成候选数据；有限次数的接受率不需要恰好等于 78.54%。

两个特别容易写错的版本

错误一：返回 unit_vector(p)。这会把圆里面的点全部推到圆周上。你要的是一整块圆盘，不是一个手镯。

错误二：半径直接均匀随机，角度也均匀随机。这样会让点偏向圆心，因为外圈面积更大，却得到同样数量的半径区间。若用极坐标均匀采样，应取 r=sqrt(U)、θ=2πV，U、V 独立均匀分布于 [0,1)。教材的拒绝采样更容易直观看懂。

本地译文在这个函数前展示的 unit_vector 声明把形参写成 u，函数体却使用 v，这是笔误。你项目里现有的 unit_vector(const vec3& v) 是一致的，不要照着那个笔误修改。

13.2③ 把平面上的小圆盘搬进三维世界

先用生活里的话说：刚才桌面上的圆盘用“横着多少、竖着多少”表示。相机歪了以后，桌面也要跟着歪。我们用第 12 章的 u 和 v 把这个圆盘抬起来，放到相机所在的位置。
C++ · 对照你的项目变量名
double radius = focus_dist * std::tan(degrees_to_radians(defocus_angle / 2));
defocus_disk_u = radius * u;
defocus_disk_v = radius * v;
C++ · 对照你的项目变量名
point3 defocus_disk_sample() const {
    vec3 p = random_in_unit_disk();
    return camera_center + p.x() * defocus_disk_u
                         + p.y() * defocus_disk_v;
}

p.x() 说“沿相机右边走多少份半径”；p.y() 说“沿相机上边走多少份半径”。先走这两步，再加上相机中心，就得到一个世界坐标里的起点。

A = C + px*(R*u) + py*(R*v) 默认相机：C=(0,0,0)，u=(1,0,0)，v=(0,1,0) R=0.3，p=(0.4,−0.2,0) A=(0,0,0)+0.4*(0.3,0,0)−0.2*(0,0.3,0) =(0.12,−0.06,0)

这个点离相机中心的距离约 0.1342，小于半径 0.3。相机旋转后，仍然使用完全一样的公式，只是 u、v 改变了。

为什么这里不用 w？

因为圆盘只在相机的左右、上下方向展开，厚度为零。增加 w 分量会把起点放到圆盘前后，变成三维体积采样。前面单位圆盘的 z=0，也正是这个意思。

因为 u、v 正交且单位长度，所以位移的长度平方为 R²*(px²+py²)。这保证原来在单位圆中的点，搬过去后仍在半径为 R 的圆中，而不会变成歪斜椭圆。

13.2④ 两个随机：小格里挑终点，镜头里挑起点

第 8 章已经在像素格内随机选位置；第 13 章再加入一个独立随机：镜头圆盘内的起点。两者同时存在，职责不同。

C++ · 第 13 章 get_ray()
ray get_ray(int i, int j) const {
    vec3 offset = sample_square();
    point3 pixel_sample = pix100Loc
        + (i + offset.x()) * pixel_delta_u
        + (j + offset.y()) * pixel_delta_v;
    point3 ray_origin = (defocus_angle <= 0)
        ? camera_center : defocus_disk_sample();
    vec3 ray_direction = pixel_sample - ray_origin;
    return ray(ray_origin, ray_direction);
}
选图像采样位置。sample_square() 给出格子内部偏移，计算出焦平面上的 pixel_sample。
选镜头起点。关闭散焦时用中心，开启时从圆盘中挑一点。
重算方向。方向必须是 pixel_sample − ray_origin。
追踪并平均。ray_color() 求一次样本，多个样本累加，最后乘 1/samples_per_pixel。
假设 P=(0.5,0.2,−3.4) 起点 A₁=(0,0,0) → 方向 D₁=(0.5,0.2,−3.4) 起点 A₂=(0.1,−0.05,0) → 方向 D₂=(0.4,0.25,−3.4) A₁+D₁=P，A₂+D₂=P：都能到达同一个采样点。
如果换了 ray_origin，却仍然减 camera_center 来算方向，那么第二条射线会平行偏移，不能在焦平面指定点会合。这是散焦代码里最关键的一类错误。

实际相邻样本通常也使用不同 pixel_sample，它们并不全部汇聚于同一个精确点，而是落在同一个像素的小区域。讲几何时固定一个终点，是为了单独展示“镜头起点变化”的效果，和抗锯齿并不矛盾。

完整实现：从第 12 章升级到第 13 章

改动集中在两个文件：vec3.h 增加圆盘采样工具，camera.h 增加散焦参数与圆盘基向量，并替换初始化和射线生成逻辑。材质散射函数仍照旧。

位置增加或替换什么
vec3.h 工具函数区域加入 random_in_unit_disk()，位置在 vec3 类和相关运算符定义之后
camera 的 publicdouble defocus_angle=0；double focus_dist=10
camera 的 privatevec3 defocus_disk_u, defocus_disk_v
initialize()用 focus_dist 设置视口尺寸和位置；计算圆盘两条半径向量

camera 的 private 函数加入 defocus_disk_sample()
C++ · 第 13 章 initialize()
void initialize() {
    image_h = int(image_w / aspect_ratio);
    if (image_h < 1) image_h = 1;
    pixel_samples_scale = 1.0 / samples_per_pixel;

    camera_center = lookfrom;
    double distance = focus_dist; // 对焦距离独立于 lookat
    double theta = degrees_to_radians(vfov);
    double h = std::tan(theta / 2);
    double viewport_h = 2 * h * distance;
    double viewport_w = viewport_h * (double(image_w) / image_h);

    w = unit_vector(lookfrom - lookat);  // 朝后
    u = unit_vector(cross(vup, w));     // 朝右
    v = cross(w, u);                   // 朝上

    vec3 viewport_u = viewport_w * u;
    vec3 viewport_v = viewport_h * (-v); // 图像行号向下增加
    pixel_delta_u = viewport_u / image_w;
    pixel_delta_v = viewport_v / image_h;

    point3 viewportLeft = camera_center - distance * w
                       - viewport_u / 2 - viewport_v / 2;
    pix100Loc = viewportLeft + 0.5 * (pixel_delta_u + pixel_delta_v);
    double radius = focus_dist * std::tan(degrees_to_radians(defocus_angle / 2));
    defocus_disk_u = radius * u;
    defocus_disk_v = radius * v;
}

#pragma once

// 延用本项目的头文件组织：main.cpp 先包含 rtweekend.h。
class camera {
public:
    double aspect_ratio = 16.0 / 9.0;
    int image_w = 400;
    int samples_per_pixel = 10;
    int max_depth = 10;

    double vfov = 90;
    point3 lookfrom = point3(0, 0, 0);
    point3 lookat = point3(0, 0, -1);
    vec3 vup = vec3(0, 1, 0);
    double defocus_angle = 0;
    double focus_dist = 10;

    void render(const hittable& world) {
        initialize();
        std::cout << "P3\n" << image_w << ' ' << image_h << "\n255\n";
        for (int j = 0; j < image_h; ++j) {
            std::clog << "\rScanlines remaining: " << image_h - j << ' ' << std::flush;
            for (int i = 0; i < image_w; ++i) {
                color pixel_color(0, 0, 0);
                for (int sample = 0; sample < samples_per_pixel; ++sample) {
                    ray r = get_ray(i, j);
                    pixel_color += ray_color(r, max_depth, world);
                }
                write_color(std::cout, pixel_samples_scale * pixel_color);
            }
        }
        std::clog << "\rDone.                 \n";
    }

private:
    int image_h;
    double pixel_samples_scale;
    point3 camera_center;
    point3 pix100Loc;
    vec3 pixel_delta_u, pixel_delta_v;
    vec3 u, v, w;
    vec3 defocus_disk_u, defocus_disk_v;

    void initialize() {
        image_h = int(image_w / aspect_ratio);
        if (image_h < 1) image_h = 1;
        pixel_samples_scale = 1.0 / samples_per_pixel;

        camera_center = lookfrom;
        double distance = focus_dist; // 对焦距离独立于 lookat
        double theta = degrees_to_radians(vfov);
        double h = std::tan(theta / 2);
        double viewport_h = 2 * h * distance;
        double viewport_w = viewport_h * (double(image_w) / image_h);

        w = unit_vector(lookfrom - lookat);  // 朝后
        u = unit_vector(cross(vup, w));     // 朝右
        v = cross(w, u);                   // 朝上

        vec3 viewport_u = viewport_w * u;
        vec3 viewport_v = viewport_h * (-v); // 图像行号向下增加
        pixel_delta_u = viewport_u / image_w;
        pixel_delta_v = viewport_v / image_h;

        point3 viewportLeft = camera_center - distance * w
                           - viewport_u / 2 - viewport_v / 2;
        pix100Loc = viewportLeft + 0.5 * (pixel_delta_u + pixel_delta_v);
        double radius = focus_dist * std::tan(degrees_to_radians(defocus_angle / 2));
        defocus_disk_u = radius * u;
        defocus_disk_v = radius * v;
    }

    vec3 sample_square() const {
        return vec3(random_double() - 0.5, random_double() - 0.5, 0);
    }

    ray get_ray(int i, int j) const {
        vec3 offset = sample_square();
        point3 pixel_sample = pix100Loc
            + (i + offset.x()) * pixel_delta_u
            + (j + offset.y()) * pixel_delta_v;
        point3 ray_origin = (defocus_angle <= 0)
            ? camera_center : defocus_disk_sample();
        vec3 ray_direction = pixel_sample - ray_origin;
        return ray(ray_origin, ray_direction);
    }
    point3 defocus_disk_sample() const {
        vec3 p = random_in_unit_disk();
        return camera_center + p.x() * defocus_disk_u
                             + p.y() * defocus_disk_v;
    }

    color ray_color(const ray& r, int depth, const hittable& world) const {
        if (depth <= 0) return color(0, 0, 0);
        hit_record rec;
        if (world.hit(r, interval(0.001, infinity), rec)) {
            ray scattered;
            color attenuation;
            if (rec.mat->scatter(r, rec, attenuation, scattered))
                return attenuation * ray_color(scattered, depth - 1, world);
            return color(0, 0, 0);
        }
        vec3 unit_direction = unit_vector(r.Dir());
        double a = 0.5 * (unit_direction.y() + 1.0);
        return (1.0 - a) * color(1, 1, 1) + a * color(0.5, 0.7, 1.0);
    }
};

这份版本已包含第 12 章能力，不需要把两个 camera 类同时保留。代码里的局部 distance 只是 focus_dist 的别名；不再保留旧的固定 focal_length 成员。

怎么对焦：lookat 和 focus_dist 的关系

情况一：希望瞄准的点正好在焦平面上

C++ · 对照你的项目变量名
cam.lookfrom = point3(-2, 2, 1);
cam.lookat = point3(0, 0, -1);
cam.vup = vec3(0, 1, 0);
cam.vfov = 20;
cam.focus_dist = (cam.lookfrom - cam.lookat).length(); // 约 3.464102
cam.defocus_angle = 2.0;

这种写法很直观：你注视的目标点恰好处于视线轴上，它的轴向深度等于两点距离，所以就把距离设成这个长度。

情况二：希望屏幕偏左的一颗球对焦

设球上希望清楚的点是 Q，相机前向单位向量是 −w。要把它放到焦平面，应取轴向深度：

focus_dist = dot(Q − lookfrom, −w)

它不是一般意义上的 length(Q-lookfrom)。只有 Q 恰好在视线轴上，两者才相等；离轴点要投影到前向方向。计算出的深度还必须大于 0，目标应位于相机前方。

教材的参数为什么是 3.4？

(−2,2,1) 到 (0,0,−1) 的距离约为 3.4641。教材选择 3.4，焦平面稍靠近相机；再使用较大的 10° 散焦角，方便观察效果。它是一个演示选择，不是所有场景都应固定填写的魔法数字。

cam.vfov = 20;
cam.lookfrom = point3(-2, 2, 1);
cam.lookat = point3(0, 0, -1);
cam.vup = vec3(0, 1, 0);

排错与练习：一步一步看到正确的模糊

建议做四张同场景对比图

  1. A：defocus_angle=0。先确认针孔版本构图正确。
  2. B：小角度，例如 1°。对焦目标附近应较清楚，其他深度开始模糊。
  3. C：加到 5°。离焦区域更明显地散开，但采样不足时噪声也更显眼。
  4. D：角度固定，只移 focus_dist。看清晰区域怎样在前后移动；不要同时移动相机，否则很难比较。
问题原因和检查方法
画面只是抖，没有明显会合平面换起点后方向是否仍用了旧 center
相机转动以后散焦方向奇怪是否把圆盘固定在世界 XY 平面；应使用相机 u、v
全图只追踪一个起点是否把随机圆盘采样错误地放到 initialize()，而不是每次 get_ray()
模糊边缘像一个空心圈是否错误地 unit_vector(p)，只采了圆周
改 focus_dist 竟改变了取景角视口尺寸和中心位置是否同步使用 focus_dist
开启散焦后闪烁、颗粒明显先提高样本；确认每次起点和像素偏移都重新采样
对焦距离为 0 时异常视口与圆盘可能塌到相机点；focus_dist 必须正数
所有物体都清楚defocus_angle 是否为 0；圆盘是否太小；物体深度是否接近
练习 1：固定对焦距离，散焦角翻倍，圆盘半径也严格翻倍吗？

不严格。R=d*tan(α/2)，正切不是线性函数。不过角度很小时 tan(x)≈x，所以半径近似翻倍。

练习 2：defocus_angle=0 时，改变 focus_dist 为什么基本不改变画面构图？

射线起点都是 C；视口大小和距离一起缩放，每个相应采样点相对 C 的向量只改变长度，不改变方向。这是理想几何结论，浮点计算、随机序列和 t 下限可能造成微小差异。

练习 3：焦平面中心 P 固定，A=(0.2,0,0)、P=(0,0,−5)，direction 是多少？

direction=P−A=(−0.2,0,−5)。当 t=1 时，A+direction=P，确实会合。

试着讲给别人听：我在相机位置放了一块小圆盘，又在前方放了一张对焦方格纸。每次先在像素格子里选一个目标点，再在圆盘里选一个出发点，连接起来追踪颜色。集合平面上的东西对齐，离开它的东西会散开。
