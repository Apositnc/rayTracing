读前准备：给小相机搬个家

先用生活里的话说：想象你拿着一个空相框看玩具小熊。以前，你被规定只能站在房间中央，朝一个方向看。现在，我们让你可以走到任何地方、转头看任何目标，还能把相框转一转。这就是“可定位相机”。
站在哪里

lookfrom：相机的位置。就像你的眼睛在哪里。

看向哪里

lookat：视线瞄准的点。就像你盯着小熊的鼻子。

看得多宽

vfov：上下张开的角度。就像能看到多大一片世界。

这一章改的是第一条光线怎么从相机出发。球和材质仍按以前的规则工作。你不需要重新学球的相交公式，也不需要重写漫反射或金属。

先分三遍读：第一遍只读绿色比喻和图；第二遍跟着数字算；第三遍打开完整代码，把每一行对应到图中的一个动作。三岁小朋友可以先理解“站哪儿、看哪儿、哪边朝上”，数学和 C++ 是接下来慢慢搭起来的积木。

你需要记得的积木最朴素的解释
point3一个地址，例如房间里的 (2, 1, 3)。
vec3一支箭头，例如“向右走 2、向上走 1”。代码中和 point3 用同一个类，但含义不同。
目标点 − 出发点从出发点走到目标点的箭头。
unit_vector(a)把箭头缩放成长度 1；保留方向。零箭头不能这样处理。
ray(origin, direction)一条路：从 origin 出发，沿 direction 前进。

12.1① 视口：放在眼前的一张透明方格纸

先用生活里的话说：你在眼睛前举一张透明方格纸，每个小格代表照片里的一个像素。从眼睛连到某个小格，再把线延长出去，撞到什么，就问那个东西该是什么颜色。

图片是二维的，方格纸的位置却在三维世界里。屏幕上的第 (i, j) 个像素，会对应到三维视口上的一个小区域。视口不是一块会挡住光线的实体物体，它只是计算方向的辅助工具。

把相机中心记作 C，把某个采样点记作 P：

射线起点 = C 射线方向 = P − C 射线上任意一点 = C + t(P − C)

这里的 t 是“走了多少份方向向量”，不一定是实际距离。因为我们的 direction 一般没有归一化，不能把 t 直接读成“多少米”。这与后面的相机搬动无关，却是理解射线时很容易混淆的地方。

为什么先只讲上下，不讲左右？

因为一个竖直角度，再加图片宽高比，就足以确定整张方格纸。教材选择 vfov，开头的 v 就是 vertical（竖直）。横向角度通常不等于它；16:9 的照片在同样的竖直角度下，横向能看得更宽。

名词它控制什么别混淆
图像宽度 image_w横向切多少个像素格格子数量，不是世界里的长度
视口宽度 viewport_w方格纸在三维世界里有多宽世界长度，不是像素数
vfov从眼睛向上沿、下沿望去的总夹角角度，不是长度，也不是分辨率

12.1② 从一个三角形算出视口高度

先用生活里的话说：把一把折扇的扇柄放在眼睛处。张开角度越大，前方覆盖的高度越大。如果张开角度不变，把接住扇面的纸移远，纸也得变大，才能接住同样的两条边。

从侧面看，相机到视口上沿、下沿构成一个对称三角形。中间水平线把它切成两个一样的直角三角形。设相机到视口的垂直距离是 d，整个视口高度是 H，竖直视角是 θ。

整个角度 θ → 上半个三角形的角度 θ/2 整个高度 H → 上半个三角形的高度 H/2 tan(θ/2) = 对边 / 邻边 = (H/2) / d H/2 = d × tan(θ/2) H = 2 × d × tan(θ/2)

tan（正切）在这里就是“前进 1 份距离，会向上张开多少份”。不知道三角函数表也没关系，C++ 的 std::tan() 帮你计算。你要理解的是比值。

为什么既除以 2，又乘以 2？

它们处理的是不同东西：角度除以 2，因为只看上半个三角形；高度乘以 2，因为最终要把上半部分和下半部分拼起来。它们不能相互抵消。

例一：vfov = 90°，d = 1 tan(45°) = 1 → H = 2 × 1 × 1 = 2 例二：vfov = 20°，d = 1 tan(10°) ≈ 0.176327 → H ≈ 0.352654 例三：vfov = 90°，d = 2 H = 2 × 2 × 1 = 4

例二只看见一个很窄的窗口。同一颗球会占更多像素，看起来像放大了。例三窗口和距离一起翻倍，边缘方向没变，针孔相机的构图也就没变。

角度要先换成弧度

C++ · 对照你的项目变量名
double theta = degrees_to_radians(vfov);
double h = std::tan(theta / 2);
double viewport_h = 2 * h * distance;

std::tan() 接受弧度。180° 是 π 弧度，90° 是 π/2，45° 是 π/4。把数字 90 直接传进去，计算机理解为 90 弧度，结果当然不对。你的 rtweekend.h 已经有 degrees_to_radians()，不需要再写一份。

动手实验：改变视角，透明纸会怎样？

拖动视角与距离

左侧是按当前参数绘制的几何侧视图，会自动缩放以放进图框；请结合数值读图。右侧用固定高度的小物体标示其投影占画面高度的比例，物体距离固定为 5。

  1. 先让 d = 3，只改视角：角度越大，纸越高，同一个物体在照片里越小。
  2. 把视角固定为 60°，只改 d：纸的高度与 d 同比例变化，右侧的物体大小不变。
  3. 把视角调到 20°：你可以把它想成“只看中间很小的一块世界”。

12.1③ 宽高比与两个相切的球

先算实际图像高度，再反过来算视口宽度

C++ · 对照你的项目变量名
image_h = int(image_w / aspect_ratio);
if (image_h < 1) image_h = 1;
double viewport_w = viewport_h * (double(image_w) / image_h);

假设 image_w = 400，想要 16:9。400 ÷ (16/9) = 225，刚好整除。若宽度是 401，高度取整后还是 225，实际比例就成了 401/225。计算视口宽度时使用实际像素比例，可以避免“声明的比例”和真正输出的比例不一致。

double(image_w) 让除法按小数计算。400/225 若双方都是整数，在 C++ 里只会得到 1，而不是约 1.7778。这里少一个强制转换，就可能把圆球压扁或拉长。

教材为什么选 R = cos(π/4)？

教材把两个球心放在 (−R, 0, −1) 与 (R, 0, −1)，半径都是 R。球心间距为 2R，正好等于两个半径相加，所以它们相切。相切这件事对任何正 R 都成立。

取 R = cos(π/4) ≈ 0.7071 只是教材的具体测试尺寸，不是相机公式必须使用的常量。两个颜色不同的球很适合检查左右、比例和视角。

展开：可以作为第 12 章第一轮测试的 main.cpp
C++ · 第 12 章测试场景
#include "rtweekend.h"
#include "hittable_list.h"
#include "sphere.h"

int main() {
    hittable_list world;
    double R = std::cos(pi / 4);
    auto blue = make_shared<lambertian>(color(0, 0, 1));
    auto red  = make_shared<lambertian>(color(1, 0, 0));
    world.add(make_shared<sphere>(point3(-R, 0, -1), R, blue));
    world.add(make_shared<sphere>(point3( R, 0, -1), R, red));

    camera cam;
    cam.aspect_ratio = 16.0 / 9.0;
    cam.image_w = 400;
    cam.samples_per_pixel = 30;
    cam.max_depth = 20;
    cam.vfov = 90;
    cam.lookfrom = point3(0, 0, 0);
    cam.lookat = point3(0, 0, -1);
    cam.vup = vec3(0, 1, 0);
    cam.render(world);
}
本场景只使用漫反射，你当前项目已有这个材质。先测试它，再测试玻璃球；这样相机问题与玻璃材质问题不会混在一起。

12.2① 站哪儿、看哪儿、头顶朝哪儿

先用生活里的话说：把相机想象成一个小人：lookfrom 是脚下的地址；lookat 是它盯着的玩具；vup 是你告诉它“头顶大概应该朝这个方向”。小人搬到哪里，它自己的前后左右也跟着改变。
C++ · 对照你的项目变量名
double vfov = 90;
point3 lookfrom = point3(0, 0, 0);
point3 lookat   = point3(0, 0, -1);
vec3 vup       = vec3(0, 1, 0);

为什么两个点还不够？

你站着不动，盯住门把手，视线方向已经固定了。但你仍然可以把头向左肩歪、向右肩歪，看到的画面会旋转。这叫滚转（roll）。所以我们还需要 vup 来约束画面的“上”。

vup 只是向上的参考，不一定就是最后的相机上方向

当你低头看地面时，世界的上方 (0,1,0) 不再垂直于你的视线。真正的相机上方向必须在“和视线垂直”的平面里。接下来用叉积重新算出的 v 才是它。

lookat 只需要定义方向。第 12 章顺便用两点距离摆放视口；到了第 13 章，它不再自动决定对焦距离。不要把“正在瞄准的点”和“对焦平面”永久绑在一起。

操作代码里改变什么肉眼效果
向右走一步只改 lookfrom；若还盯着同一点，lookat 不改观察方向与遮挡关系可能都变
整体平移并保持朝向给 lookfrom 和 lookat 加同一个位移观察位置变，方向不变
原地转头lookfrom 不动，改 lookat看向别的地方
歪头在保持视线的前提下调整 vup画面滚转
缩窄取景范围减小 vfov同一位置的物体在图上变大

12.2② u、v、w：给相机一套自己的方向

先用生活里的话说：世界有一套“东南西北”，但小人还有一套“我的右、我的上、我的后”。小人转身以后，它的右边不一定是世界的右边。这三支跟着小人转的箭头，就是 u、v、w。
u → 右

沿着照片从左走到右。

v ↑ 上

沿着照片从下走到上。

w ← 后

从目标指回相机；看出去的方向是 −w。

这三支箭头互相垂直，长度都是 1，叫正交归一基底。不用怕这个名字：正交 = 垂直，归一 = 长度变成 1，基底 = 用来描述方向的三把尺子。

C++ · 对照你的项目变量名
w = unit_vector(lookfrom - lookat);
u = unit_vector(cross(vup, w));
v = cross(w, u);

第一行：先确定朝后

“目标 − 自己”是朝前；“自己 − 目标”就是朝后。所以 lookfrom - lookat 得到后方，再除以长度变成单位箭头。教材选“后方”当 w 是坐标约定，不能只凭变量名字猜方向。

第二行：用叉积找右边

cross(a,b) 返回一支同时垂直于 a 和 b 的箭头。垂直的方向有两边，叉积用固定的右手规则挑一边；交换顺序会翻转方向。

cross(a, b) = −cross(b, a) 默认情况：vup = (0,1,0)，w = (0,0,1) cross(vup, w) = (1,0,0) → 正好是向右

cross(vup,w) 的长度一般不为 1，因为 vup 可能和 w 斜交，也可能本身不是单位向量。因此必须再 unit_vector()。

第三行：补出真正向上

u、w 已经互相垂直且都是单位向量，所以 cross(w,u) 的长度理论上就是 1，得到 v。无需再归一化一次。计算机浮点数会有微小误差，这不改变推导。

如果你想看更数学一点的关系：v 的方向等于 vup - dot(vup,w)*w 的方向。也就是把 vup 中“沿着视线”的那一截拿掉，只留下相机平面里的向上分量。

两种非法输入要避开：① lookfrom 与 lookat 重合，没有视线方向；② vup 为零或与视线平行，叉积为零，算不出左右。几乎平行也会放大数值误差。教学代码假定输入合法；实际工具应检测后报错或换一个参考 up。

12.2③ 用两组数字把方向算出来

例一：旧相机必须原样回来

lookfrom = (0,0,0) lookat = (0,0,−1) vup = (0,1,0) w = unit((0,0,1)) = (0,0,1) u = unit(cross((0,1,0), (0,0,1))) = (1,0,0) v = cross((0,0,1), (1,0,0)) = (0,1,0) 看出去的方向 −w = (0,0,−1)

这一步很有价值：新公式在旧参数下退回旧行为，说明我们没有凭空换坐标规则。

例二：教材的斜上方相机

lookfrom = (−2,2,1)，lookat = (0,0,−1) lookfrom − lookat = (−2,2,2) 距离 d = √(4+4+4) = √12 ≈ 3.464102 w ≈ (−0.577350, 0.577350, 0.577350) u ≈ ( 0.707107, 0, 0.707107) v ≈ ( 0.408248, 0.816497,−0.408248)

检验方法不是盯着数字觉得“应该差不多”，而是算：每个向量长度约等于 1，任意两者点积约等于 0。然后检查 camera_center - d*w，它应该回到 lookat。三条检查都过，方向通常就对了。

方向实验室：转头以后，右边还在哪儿？

这是三维箭头的二维斜投影，所以屏幕上看起来未必是直角；是否垂直要看点积。箭头颜色：红 u，绿 v，蓝 w；虚线是看出去的 −w。

想一想：相机正朝 −w 看，为什么把视口中心写成 C − d*w？

12.2④ 把透明方格纸搬到正确的位置

现在我们有了相机的右、上、后，就可以把旧代码里写死的世界方向全部换掉。

C++ · 对照你的项目变量名
vec3 viewport_u = viewport_w * u;
vec3 viewport_v = viewport_h * (-v);

u 只有方向和单位长度；乘上 viewport_w，才成为“跨完整张纸的水平箭头”。v 向上，而图像 j 从第一行往下增加，所以竖直边缘要用 -v。

走路式拆解左上角公式

视口中心 M = C − d*w 左上角 L = M − viewport_u/2 − viewport_v/2 第一个像素中心 P₀₀ = L + 0.5*(pixel_delta_u + pixel_delta_v)
先从相机走到纸的中心。 C − d*w：朝前走 d。
再向左走半张纸。 减去 viewport_u/2。
再向上走半张纸。 viewport_v 指向下，减去它就会向上。
进入第一个小格的中心。 从左上边界向右半格、向下半格。
“两个减号”不是死记硬背出来的。第二个减号确实在做“向上走”，因为它减去的是一支朝下的箭头。不要看到变量里有 v 就忘记 viewport_v 已经含了负号。

一个能用纸笔算完的 4 × 2 小图

C=(0,0,0)，d=1，vfov=90°，图像 4×2 viewport_h=2，viewport_w=4 viewport_u=(4,0,0)，viewport_v=(0,−2,0) pixel_delta_u=(1,0,0)，pixel_delta_v=(0,−1,0) 视口中心 M=(0,0,−1) 左上角 L=(−2,1,−1) 第一个像素中心 P₀₀=(−1.5,0.5,−1) 不加随机偏移时，第 i=2、j=1 个像素： P=P₀₀+2*(1,0,0)+1*(0,−1,0) =(0.5,−0.5,−1)

注意下标从 0 开始：i=2 是第三列，j=1 是第二行。你的变量 pix100Loc 实际承担的是教材 pixel00_loc 的工作，并不是“第 100 个像素”。为了方便与你的代码对照，这里保留原名。

12.2⑤ 接回采样：每个小格里面挑一个点

先用生活里的话说：一个像素小格不是一个针尖。我们可以在格子里随机戳很多下，再把每次看到的颜色平均。这样格子边上刚好有一颗球时，结果就能反映“这个格子被球覆盖了多少”。
C++ · 对照你的项目变量名
ray get_ray(int i, int j) const {
    vec3 offset = sample_square();
    point3 pixel_sample = pix100Loc
        + (i + offset.x()) * pixel_delta_u
        + (j + offset.y()) * pixel_delta_v;
    point3 ray_origin = camera_center;
    vec3 ray_direction = pixel_sample - ray_origin;
    return ray(ray_origin, ray_direction);
}

sample_square() 返回 x、y 各自落在 [−0.5, 0.5) 的偏移。因为 pix100Loc 已经是格子中心，所以偏移以中心为零，而不是以左上角为零。

仍用前面的 4×2 例子：i=2，j=1 offset=(0.2,−0.3,0) P=(−1.5,0.5,−1)+2.2*(1,0,0)+0.7*(0,−1,0) =(0.7,−0.2,−1)

你当前代码里需要特别留意的一行

C++ · 对照你的项目变量名
// 当前版本的纵向项：
+ ((j + offset.x()) * pixel_delta_v)

// 讲解版本改成：
+ ((j + offset.y()) * pixel_delta_v)

如果横向和纵向都用同一个随机数，采样点会沿小格的一条对角线活动，而不是覆盖整个小格。画面仍可能“能看”，却不是我们想要的二维均匀采样。每个坐标分别使用 x、y，才能保留两维变化。

ray_direction = pixel_sample - ray_origin 不需要归一化才能求交。你当前球体求交代码用 a = dot(direction,direction)，允许任意非零方向长度。需要单位方向的材质、天空计算会在各自位置归一化。

完整实现：按你的 camera.h 一次串起来

先看核心的 initialize()，每一段都对应刚才的一次搬动。

C++ · 第 12 章 initialize()
void initialize() {
    image_h = int(image_w / aspect_ratio);
    if (image_h < 1) image_h = 1;
    pixel_samples_scale = 1.0 / samples_per_pixel;

    camera_center = lookfrom;
    double distance = (lookfrom - lookat).length();
    double theta = degrees_to_radians(vfov);
    double h = std::tan(theta / 2);
    double viewport_h = 2 * h * distance;
    double viewport_w = viewport_h * (double(image_w) / image_h);

    w = unit_vector(lookfrom - lookat);  // 朝后
    u = unit_vector(cross(vup, w));     // 朝右
    v = cross(w, u);                   // 朝上

    vec3 viewport_u = viewport_w * u;
    vec3 viewport_v = viewport_h * (-v); // 图像行号向下增加
    pixel_delta_u = viewport_u / image_w;
    pixel_delta_v = viewport_v / image_h;

    point3 viewportLeft = camera_center - distance * w
                       - viewport_u / 2 - viewport_v / 2;
    pix100Loc = viewportLeft + 0.5 * (pixel_delta_u + pixel_delta_v);
}

需要新增的公开参数是 vfov/lookfrom/lookat/vup，私有成员新增 u/v/w。旧的固定 focal_length = 1.0 和固定 viewport_h = 2 不再使用。

C++ · 完整第 12 章 camera.h
#pragma once
#include "hittable.h"
#include "material.h"
#include "vec3.h"

// 延用本项目的头文件组织：main.cpp 先包含 rtweekend.h。
class camera {
public:
    double aspect_ratio = 16.0 / 9.0;
    int image_w = 400;
    int samples_per_pixel = 10;
    int max_depth = 10;

    double vfov = 90;
    point3 lookfrom = point3(0, 0, 0);
    point3 lookat = point3(0, 0, -1);
    vec3 vup = vec3(0, 1, 0);

    void render(const hittable& world) {
        initialize();
        std::cout << "P3\n" << image_w << ' ' << image_h << "\n255\n";
        for (int j = 0; j < image_h; ++j) {
            std::clog << "\rScanlines remaining: " << image_h - j << ' ' << std::flush;
            for (int i = 0; i < image_w; ++i) {
                color pixel_color(0, 0, 0);
                for (int sample = 0; sample < samples_per_pixel; ++sample) {
                    ray r = get_ray(i, j);
                    pixel_color += ray_color(r, max_depth, world);
                }
                write_color(std::cout, pixel_samples_scale * pixel_color);
            }
        }
        std::clog << "\rDone.                 \n";
    }

private:
    int image_h;
    double pixel_samples_scale;
    point3 camera_center;
    point3 pix100Loc;
    vec3 pixel_delta_u, pixel_delta_v;
    vec3 u, v, w;

    void initialize() {
        image_h = int(image_w / aspect_ratio);
        if (image_h < 1) image_h = 1;
        pixel_samples_scale = 1.0 / samples_per_pixel;

        camera_center = lookfrom;
        double distance = (lookfrom - lookat).length();
        double theta = degrees_to_radians(vfov);
        double h = std::tan(theta / 2);
        double viewport_h = 2 * h * distance;
        double viewport_w = viewport_h * (double(image_w) / image_h);

        w = unit_vector(lookfrom - lookat);  // 朝后
        u = unit_vector(cross(vup, w));     // 朝右
        v = cross(w, u);                   // 朝上

        vec3 viewport_u = viewport_w * u;
        vec3 viewport_v = viewport_h * (-v); // 图像行号向下增加
        pixel_delta_u = viewport_u / image_w;
        pixel_delta_v = viewport_v / image_h;

        point3 viewportLeft = camera_center - distance * w
                           - viewport_u / 2 - viewport_v / 2;
        pix100Loc = viewportLeft + 0.5 * (pixel_delta_u + pixel_delta_v);
    }

    vec3 sample_square() const {
        return vec3(random_double() - 0.5, random_double() - 0.5, 0);
    }

    ray get_ray(int i, int j) const {
        vec3 offset = sample_square();
        point3 pixel_sample = pix100Loc
            + (i + offset.x()) * pixel_delta_u
            + (j + offset.y()) * pixel_delta_v;
        point3 ray_origin = camera_center;
        vec3 ray_direction = pixel_sample - ray_origin;
        return ray(ray_origin, ray_direction);
    }

    color ray_color(const ray& r, int depth, const hittable& world) const {
        if (depth <= 0) return color(0, 0, 0);
        hit_record rec;
        if (world.hit(r, interval(0.001, infinity), rec)) {
            ray scattered;
            color attenuation;
            if (rec.mat->scatter(r, rec, attenuation, scattered))
                return attenuation * ray_color(scattered, depth - 1, world);
            return color(0, 0, 0);
        }
        vec3 unit_direction = unit_vector(r.Dir());
        double a = 0.5 * (unit_direction.y() + 1.0);
        return (1.0 - a) * color(1, 1, 1) + a * color(0.5, 0.7, 1.0);
    }
};

怎么练、怎么查错、怎么确认自己懂了

按这个顺序做，最容易定位错误

  1. 先恢复旧视角。 (0,0,0) 看 (0,0,−1)，vfov=90，vup=(0,1,0)。只改相机实现，不改场景。
  2. 测试红蓝双球。 蓝在左、红在右；球不要被拉扁。
  3. 改相机位置。 使用 (−2,2,1) 看 (0,0,−1)，确认能从斜上方观察。
  4. 把 vfov 从 90 改成 20。 球变大，取景范围变小。
  5. 试着滚转。 用与视线不平行的另一个 vup，理解画面的上方是怎么来的。
现象优先检查
画面左右镜像是否把 cross(vup,w) 写成 cross(w,vup)
看向了背后w 的减法顺序，视口是否用 C − distance*w
上下颠倒viewport_v 是否是 −viewport_h*v
球被拉伸是否用了整数除法；实际宽高比是否一致
全黑或出现 NaNlookfrom==lookat？vup 平行视线？vfov 是否接近 0° 或 180°？
拖远 lookat，物体没变小若朝向未变，针孔模型里视口和距离同时按比例扩大，这是正确现象
近处和远处相对大小变化奇怪区分“移动相机”和“缩小视角”：移动会改变透视关系，缩角主要改变取景范围

动手算三题

题 1：vfov=90°、d=3，视口高度是多少？

H = 2 × 3 × tan45° = 6。若图片为 16:9 且实际尺寸恰好符合比例，宽度为 6×16/9≈10.6667。

题 2：C=(3,0,0)，lookat=(0,0,0)，vup=(0,1,0)，u/v/w 是什么？

w=(1,0,0)，u=(0,0,−1)，v=(0,1,0)。相机朝 −X 看，照片里的右边对应世界的 −Z。

题 3：为什么不能把 pixel00_loc 直接设成 viewport_upper_left？

后者在格子边界，前者需要在第一格中心。还要向右半格、向下半格；否则整张图的采样位置偏了半个像素。
